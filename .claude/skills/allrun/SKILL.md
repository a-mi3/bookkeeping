# allrun スキル

音声メモからコンテンツ公開準備までをワンコマンドで完了させる統合パイプライン。

## フォルダ構成

```
$ROOT/
├── 00_ボイスメモ/        ← 音声ファイルを入れる（処理後は99へ）
├── 01_一時ファイル/       ← 文字起こし一時保存（ブログ記事完成後に削除）
├── 02_ブログ記事/        ← テーマごとにサブフォルダ作成
│   └── {テーマ名}/
│       └── {テーマ名}.md
├── 03_加工情報/          ← テーマごとにサブフォルダ作成
│   └── {テーマ名}/
│       ├── {テーマ名}_小学生向け解説.md
│       ├── {テーマ名}_インフォグラフィック_プロンプト.md
│       ├── {テーマ名}_X投稿_140字.md
│       └── {テーマ名}_X投稿_2000字.md
└── 99_アーカイブ/        ← 処理済み・残留ファイルの退避先
    ├── 01_一時ファイル/
    ├── 02_ブログ記事/
    └── 03_加工情報/
```

`$ROOT` = `C:\Users\ami\Downloads\Claude用\ami.kadai`

## PHASE 0 — 初期化とアーカイブ整理

### 0-1. フォルダ作成

存在しないフォルダがあれば作成する。

```powershell
@("00_ボイスメモ","01_一時ファイル","02_ブログ記事","03_加工情報",
  "99_アーカイブ","99_アーカイブ\01_一時ファイル","99_アーカイブ\02_ブログ記事","99_アーカイブ\03_加工情報"
) | ForEach-Object { New-Item -ItemType Directory -Force "$ROOT\$_" }
```

### 0-2. 残留ファイルのアーカイブ

`00_ボイスメモ` と `99_アーカイブ` **以外** のフォルダ（`01_一時ファイル`、`02_ブログ記事`、`03_加工情報`）にファイルやサブフォルダが残っている場合、すべて `99_アーカイブ` 内の対応フォルダへ移動する。

```powershell
# 01_一時ファイル → 99_アーカイブ\01_一時ファイル
# 02_ブログ記事   → 99_アーカイブ\02_ブログ記事
# 03_加工情報    → 99_アーカイブ\03_加工情報
```

移動時に同名ファイル/フォルダが存在する場合は、タイムスタンプ `_YYYYMMDD_HHmmss` を付けてリネームする。

## PHASE 1 — 文字起こし

### 1-1. 音声ファイルの列挙

`$ROOT\00_ボイスメモ` 直下の音声ファイル（.m4a .mp3 .wav .ogg .flac）を列挙する。

対象ファイルが0件なら「処理する音声ファイルがありません」と報告して終了する。

### 1-2. 文字起こしの実行

各音声ファイルについて：

1. 同名の `.txt` ファイルが `00_ボイスメモ` 内に存在するか確認する
2. `.txt` があればその内容を最優先で使用する（**推測・ダミーテキスト禁止**）
3. `.txt` がなければ以下のスクリプトで Whisper 文字起こしを実行する：

```powershell
node "${CLAUDE_SKILL_DIR}\..\transcribe\scripts\run.js" "$AUDIO_PATH"
```

4. 文字起こし結果を `$ROOT\01_一時ファイル\{ファイル名（拡張子なし）}.md` に保存する

保存フォーマット：

```markdown
---
タイトル: {ファイル名（拡張子なし）}
作成日: {ファイルの更新日 YYYY-MM-DD}
元ファイル: {ファイル名.拡張子}
タグ:
  - 文字起こし
  - 音声
---

# {タイトル}

## 全文文字起こし

{文字起こしテキスト}
```

## PHASE 2 — ブログ記事の作成

`01_一時ファイル` 内の各 `.md` ファイルについて：

### 2-1. 参考資料の収集

`$ROOT\articles` フォルダが存在する場合、内容に関連する参考資料を検索する。
関連資料が見つかれば、出典（Web URL）として記事に織り込む。

### 2-2. 記事の生成

以下のルールでブログ記事を生成する：

- **主軸は文字起こしデータ**：ユーザーの思想・体験が記事の中心
- **読者に語りかける文体**：「です・ます」調の体験談
- **構造**：タイトル → 導入 → 本論（2〜4セクション）→ まとめ → ハッシュタグ
- **タイトル**：【】で注目ワードを入れ、30〜50文字程度
- **出典リンク**は Web URL で記載する
- **note.com の見出し仕様に合わせる**：`##`（h2）を主要見出しとして使用（h1 はタイトルのみ）
- YAML フロントマターは付けない
- Obsidian 記法（`![[]]`）は使わない
- 末尾にハッシュタグを `#タグ名` 形式で5〜8個

### 2-3. 保存

1. `$ROOT\02_ブログ記事\{テーマ名}\` フォルダを作成する
2. `{テーマ名}.md` として保存する

### 2-4. 一時ファイルの削除

ブログ記事の保存が確認できたら、対応する `01_一時ファイル` 内の文字起こしファイルを削除する。

## PHASE 3 — コンテンツ加工

`02_ブログ記事` 内の各記事フォルダについて：

### 3-1. 出力フォルダの作成

`$ROOT\03_加工情報\{テーマ名}\` フォルダを作成する。

### 3-2. 4種類のコンテンツを生成

#### ① 小学生向け解説記事

**ファイル名**: `{テーマ名}_小学生向け解説.md`

- 小学3年生以上の漢字にはふりがな（カッコ書き）を付ける
- 専門用語はかみ砕いて説明する
- 「です・ます」調のやさしい文体
- 元記事の主張・結論は変えない

#### ② インフォグラフィック用プロンプト

**ファイル名**: `{テーマ名}_インフォグラフィック_プロンプト.md`

- GPT Images 2.0 にそのまま貼り付けられるプロンプトを ``` コードブロックで記載
- 画像サイズ 1080×1350px（縦長）
- レイアウト・配色・セクション構成を明記
- 「すべてのテキストは日本語で表記」を指定
- フラットデザイン・ゴシック体太字の指定
- 末尾に「使い方」4ステップを付ける

#### ③ X投稿用 140字まとめ

**ファイル名**: `{テーマ名}_X投稿_140字.md`

- 140字以内（全角基準）
- ハッシュタグ2〜3個、絵文字1〜2個
- ファイル内に実際の文字数を記載する

#### ④ X投稿用 2000字まとめ

**ファイル名**: `{テーマ名}_X投稿_2000字.md`

- 1000〜2000字で構成
- 短い段落・区切り線で読みやすく
- ハッシュタグ5〜7個
- 出典 URL は省略する
- ファイル内に実際の文字数を記載する

## PHASE 4 — note.com 下書き保存

各ブログ記事について、Chrome で note.com に下書き保存する。

### 4-1. note.com を開く

Chrome MCP ツール（`mcp__Claude_in_Chrome__*`）を使って note.com にアクセスする。
すでにログイン済みであることを前提とする。

### 4-2. 新規記事作成ページを開く

`https://note.com/notes/new` にアクセスして記事作成画面を開く。

### 4-3. 記事内容の入力

1. **タイトル**: 記事の `#` 見出し（h1）のテキストをタイトル欄に入力
2. **本文**: h1 以降の本文を入力する
   - note.com では `##` が h2（大見出し）、`###` が h3（小見出し）になる
   - 画像がある場合（`03_加工情報` 内のインフォグラフィック等）はファイルパスから画像を挿入する
3. **ハッシュタグ**: 記事末尾のタグを note のタグ欄に入力する

### 4-4. 下書き保存

「下書き保存」ボタンをクリックして保存する。
保存完了を確認する。

## PHASE 5 — 音声ファイルのアーカイブ

すべての処理が完了したら、`00_ボイスメモ` 内の処理済み音声ファイルを `99_アーカイブ` 直下へ移動する。

```powershell
Move-Item "$ROOT\00_ボイスメモ\{ファイル名}" "$ROOT\99_アーカイブ\"
```
